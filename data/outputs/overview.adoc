= Losant CLI
:description: Manage your Losant Application and it's resources on your local disk.
:sidebar_position: 1
:sidebar_label: Overview
:revdate: 2026-03-26

Losant CLI is a command line tool to help manage your xref:applications/overview.adoc[Losant Application] and its resources. It easily lets you manage xref:experiences/views.adoc[Experience Views], xref:experiences/versions.adoc[Experience Versions], xref:data-tables/overview.adoc[Data Tables], and xref:applications/files.adoc[Files] in your Applications.

== Installation

The Losant CLI requires you to download and install Node.js version 14 or higher and NPM. You can use the https://nodejs.org/en/download/[Node installer] to install both Node and NPM. Once you have those installed, run `npm install -g losant-cli`. To check that you have install Losant CLI properly run `losant --help`, and that prints all the commands you have available. See our https://github.com/Losant/losant-cli[GitHub repository] if you are having trouble installing.

== Usage

Here are all the following resources the CLI supports:

* xref:cli/experience.adoc[*Experiences*]: Manage xref:experiences/views.adoc[Experience Views], and xref:experiences/versions.adoc[Versions] from the command line.
* xref:cli/files.adoc[*Files*]: Manage xref:applications/files.adoc[public Application Files] from the command line.
* xref:cli/data-tables.adoc[*Data Tables*]: Manage xref:data-tables/overview.adoc[Data Tables] from the command line.

== Setup

Before you get started, there are a couple things you have to configure first. The first is setting up your user profile for the Losant CLI. This can be done by either by the xref:#_login[login] command or the xref:#_set_token[set-token] command. Either allows your user to access applications and their resources.

=== Login

After installing, one way to set up your user profile is to run the command `losant login`. This prompts you to enter your Losant account email address. If your user is *not* connected to a Single Sign-On Provider, you is prompted to enter your password, and optionally your multi-factor authentication code. *If you do not have multi-factor authentication enabled, just hit enter to skip multi-factor authentication.*

image::cli/login.png[Losant Login,title="Login"]

If you account is connected to a Single Sign-On Provider, you is prompted to enter a xref:#_creating_a_user_token[User Token].

image::cli/login-token.png[Losant Login Token,title="Login Token"]

Once you have successfully authenticated with our API, a file is created at `~/.losant/.credentials.yml` containing your authentication token. This token is used across all your Losant configured directories.

image::cli/login-success.png[Losant Success Login,title="Login Success"]

If authentication fails you is prompted to re-enter your email, password and multi-factor authentication.

image::cli/login-failure.png[Losant Retry Login,title="Login Retry"]

=== Set-Token

image::cli/set-token.png[Losant Set-Token,title="Set-Token"]

The second way to set up your user profile is to run the command `losant set-token [token]`. After installation, running this command prompts you to enter a xref:#_creating_a_user_token[User Token] or pass in the User Token as the command argument to avoid being prompted. The set-token command is an easy way to give a non-Losant user access to a specific application or all your applications without having to give them the full credentials to the UI.

==== Creating a User Token

A xref:user-accounts/user-tokens.adoc[User Token] can be created in the xref:user-accounts/user-tokens.adoc#_generating_an_api_token[UI] or through the xref:rest-api/user-api-tokens.adoc#_post[API]. If you are using the UI to create a User Token, select the "CLI developer" permission option. This permission option scopes the exact permissions needed to manage only the resources that can be managed in the CLI. If you are creating a User Token with the API, set the field `scope` to `all.User.cli`.

=== Configure

After you have successfully set up your user profile, you are now ready to configure a directory.

Create or go to a directory that you want to keep your Losant Application resources, then run `losant configure`. This links the current directory to one of your Losant Applications.

image::cli/configure.png[Losant Configure,title="Configure"]

When you run this command, you is prompted to give a (or part of a) Losant Application name. If multiple Applications come back with similar names we present you with a list to choose from. If you don't find the application you are looking for, choose `none of these, search again`, and it re-prompts you for another Application name.

Once you have picked the Losant Application, it will automatically try to download your Application's xref:experiences/views.adoc[Experience Views]. It will then prompt you to download your xref:applications/files.adoc[Application's Files] followed by your xref:data-tables/overview.adoc[Application's Data Tables].

image::cli/configure-success.png[Losant Configure Success,title="Configure Success"]

Once you have configured the directory, you notice a few newly created directories in your configured directory.

==== Losant CLI Directories

* `.losant/`: This is where we store dotfiles with your YAML configuration.
* `dataTables/`: This is where all your local data tables is stored as CSV files.
* `experience/components/`: This is where all your local experience components is.
* `experience/pages/`: This is where all your local experience pages is.
* `experience/layouts/`: This is where all your local experience layouts is.
* `files/`: This is where all your local files is. The Files directory matches the top-level directory on your Application's xref:applications/files.adoc#_public_files[public Files]. For example, if on Losant you have a public file at `/foo/bar/helloworld.txt`, that file is downloaded and placed at `files/foo/bar/helloworld.txt`. (xref:applications/files.adoc#_private_files[Private files] are not supported by the Losant CLI.)
