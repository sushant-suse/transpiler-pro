= 🏗 System Architecture & Module Interaction
:description: Architecture documentation for the Transpiler-Pro documentation pipeline.

Transpiler-Pro is built on a *Decoupled Logic Architecture*. The Python source code remains "pure"—it contains the core algorithms for transformation but relies on externalized data. It dynamically consumes the *Official SUSE Style Guide* and a *Persistent Knowledge Base* to drive its decision-making.

== 🛰 Orchestration Layer

* `cli.py` - The central conductor utilizing *Typer*. It manages the command lifecycle (`sync`, `x-convert`, `y-repair`, `audit`, and `full-run`). It handles path resolution via `utils/paths.py`, ensures directory mirror-integrity across external paths, and orchestrates the final parity audit to ensure 100% content retention.
* `utils/logger.py` - The Audit Engine. It transforms raw linter violations into a clickable Markdown report. It utilizes the `file://` protocol for absolute URI linking, allowing developers to jump directly from the report to the specific line in their IDE (for example, VS Code).

== ⚙️ Core Transformation & Repair Layer

=== 1. `core/converter.py` (The Structural Engineer)

Handles the "Shield-Transpile-Restore" workflow and directory structural integrity:

* *Shielding* - Protects complex Markdown elements (Tabs, Collapsibles, XREFs) from being mangled by Pandoc using regex-defined markers.
* *Asset Mirroring* - **(New)** Identifies non-convertible files (for example, `_category_.yml`, images) and mirrors them to the output directory, preserving the Antora component hierarchy.
* *Restoration* - Replaces markers with high-fidelity, Antora-compliant AsciiDoc blocks (for example, `[%collapsible]` or `[tabs]`).

=== 2. `core/linter.py` (The Style Sensor)

Integrates the *Vale CLI* as a diagnostic engine. It maps the *SUSE Style Guide* repository against the generated AsciiDoc to extract correction metadata (Line Numbers, Severity, and Rule IDs). This provides the data required for both automated healing and manual audit logging.

=== 3. `core/repair.py` (The Recursive NLP Healer)

The linguistic intelligence layer, utilizing *spaCy NLP* and surgical string manipulation:

* *Proximity Fallback Subject Detection* - Identifies sentence subjects by scanning backwards from auxiliary verbs, ensuring correct conjugation in complex clauses.
* *Surgical Replacement* - Uses exact character offsets from the NLP model to replace text, preventing "collision bugs" where one rule overwrites another.
* *Morphological Conjugation* - Dynamically generates third-person singular forms (for example, `verify` -> `verifies`).

=== 4. `core/validator.py` (The Parity Guardian)

**(New)** A dedicated engine that performs a deep comparison between the Markdown source and the AsciiDoc output:

* *Branding-Aware Coverage* - Strips syntax and compares "significant" words. It utilizes the Knowledge Base to ensure intentional branding fixes (for example, `wifi` -> `Wi-Fi`) are treated as matches rather than content loss.
* *Structural Parity* - Confirms the count of headings and tables matches the source exactly.
* *Snippet Protection* - Triggers a critical failure if any code blocks are missing or mangled during the transformation process.

=== 5. `core/fixer.py` (The Rule-Based Engine)

A surgical regex layer that handles non-grammatical style violations. It processes suggestions from the linter, such as removing editorializing phrases or applying specific term substitutions, while maintaining guardrails against the NLP engine.

== 🧠 The Persistent Knowledge Base (`knowledge_base.json`)

The `knowledge_base.json` file serves as the **External Brain** of the pipeline. Its significance lies in its ability to steer the code's behavior without requiring a re-deployment of the source logic.

* *automated_fixes* - Acts as a Global Branding Guardrail. It enforces high-priority casing (for example, `SUSE`, `Wi-Fi`, `IP`). The pipeline applies these with negative lookarounds to ensure they never break technical strings like URLs or image paths.
* *ignored_rules* - A safety valve that tells the Linter to ignore specific SUSE style rules that may conflict with project-specific requirements.
* *learned* - The "Auto-Heal" memory. When the linter suggests a spelling fix, the fixer "learns" this correction and saves it here, automating the fix for all future occurrences across the entire documentation set.

== 🔄 The Multi-Phase Data Flow

. *Synchronization (`sync`)* - Pulls the latest rules from the official openSUSE style guide repository.
. *Ingestion* - Markdown is pulled from provided `--input` paths (defaulting to `data/inputs/`).
. *Conversion (Phase X)* - Structural transformation occurs via `converter.py`. Asset Mirroring ensures `.yml` and images are preserved. Raw AsciiDoc is saved to `data/intermediate/`.
. *Linguistic Healing (Phase Y)* - 
** *Diagnostics*: The Linter generates a "Violation Map."
** *NLP Pass*: `repair.py` performs tense shifting and subject-verb agreement.
** *Regex Pass*: `fixer.py` executes branding swaps and linter-driven corrections.
. *Content Parity Audit (Phase Z)* - **(New)** `validator.py` compares the source Markdown against final AsciiDoc. It calculates word coverage and verifies structural integrity (headings, tables, code blocks).
. *Final Reporting* - The CLI displays "Fixed vs. Remaining" style metrics and the final Parity Dashboard.
